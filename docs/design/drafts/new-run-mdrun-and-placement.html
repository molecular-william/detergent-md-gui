New run — the mdrun device, and how the detergents are placed

Static mock for the Protein-Detergent workspace. The device selector applies to every run type; the placement card only to pdc. The three pictures at the bottom are the behaviour being proposed, drawn to scale in nothing but intent.

Three proposals: (1) name the GPU mdrun runs on, and record its name with the run; (2) place detergents by their bodies with drawn orientations, so nothing intersects the protein; (3) size the shell from the subunits actually selected instead of the whole complex's default radius.
Execution

Where it runs

GROMACS 2026.3 · MPI build · 1 rank × 8 OpenMP threads

every run type

The list is read from the host (/api/run/devices), and an index that no longer exists is refused when the run is prepared — with the devices that do, named — rather than by mdrun three stages later. A host with no GPU offers no device and says so.

Recorded per run: environment.devices (everything present at prepare) and resource_usage.gpu (the one chosen, by index, name and UUID). The run view shows the name beside the thread budget, so two runs are comparable without reading their logs.
Detergent placement

How the belt is built

Protein 1at9 · 4 chains · DDM · 60 detergents

pdc only
ABCD

The selection decides the protein, the box, and — proposed — the shell. With A and B the hydrophobic region is about half the complex's, so the shell closes in around those two subunits instead of holding the space of all four.

The floor is what radius_nm becomes: today it is the radius, which is why one subunit gets a whole-complex micelle. The measured shell wins when it is larger.
