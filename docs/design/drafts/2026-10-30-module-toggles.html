Switching installed modules on and off

The toggles change which workspaces this dashboard shows. Nothing is unloaded: the module's API, run types and recorded-code resolvers stay live, so existing runs keep opening and analysing. A change applies when the page is reloaded — the banner in each design is the only new state.

  • On — workspace appears in the navigation and its run types appear in New run.
  • Off — workspace and its run types are hidden; its panels are reachable only if you already have a run of that type open.
  • Not installed — listed but not switchable, so a missing dependency is visible rather than forgotten.

C · A full page inside the engine workspace. Most room for explanations and "not installed" guidance; one navigation step away from where the reader is.

Recommendation

A is the best fit: the workspaces are already a small, stable set, so a rail costs 276px and teaches the module concept in place. B is the smallest change if the rail is too much layout. C belongs beside A as the place to explain modules, not as the only way to reach them.

Implementation notes: the switch writes a workspace-scoped setting; the server filters workspaces and New run's run types on the next page load; a disabled workspace's URL answers 404 with a link to the enabled ones; the current workspace falling out of the set lands on the first remaining one. The rail's collapse state is remembered in localStorage.
