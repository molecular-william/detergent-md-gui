Giving each detergent an equilibrated conformation

Today every detergent in a build is the template's one rigid conformation, rotated into place. This draft adds a second source: a library of shapes sampled from micelle-only simulations, from which each detergent draws its own entry and its own twist about the head axis.

The library is named by the source run ids, built on demand, and not tracked in git. It lives under the workspace as a self-contained directory that can be copied between workspaces; the run records its key and digest, not the bytes. Size is fixed at 2,000 conformations per detergent, chosen to span the ensemble rather than by taking the first 2,000.

What the panel sends when the library is on: conformation_library: {runs: ["<id>", …], size: 2000, seed: 0}. Absent means today's behaviour, byte for byte.

How the library is built and where it lives

Each source trajectory is read once: whole detergent molecules are taken from the production frames, made whole, checked against the mapping's bond geometry, and turned into a local frame (head at the origin, head-ward axis along +z). The candidates are then split into 2,000 strata over four shape descriptors (length, radius of gyration, reach, radial spread) and one representative is taken per stratum.

The result is workspace/dashboard/conformations/DDM/<key>/library.json with a library.sha256 beside it. It is not tracked in git; the directory is self-contained and can be copied into another workspace. A copied library is accepted when its digest matches, a hand-edited one is refused, and a rebuild that would change the digest is refused rather than silently swapped.

What this draft fixes, and what it leaves to the implementation

Decisions encoded

  • One or several source runs, chosen by checkbox; the payload carries the ids.
  • 2,000 conformations per detergent by default, with a size field for the operator and a refusal when the pool is smaller.
  • The library is named by run id, rebuilt on demand and cached; nothing is tracked in git; the directory is meant to be copied by hand.
  • The panel sends the spec, never the conformations: the server resolves/rebuilds and records the key.
  • Off is the default and leaves every existing build byte-identical.

States this draft shows

  • Off — one rigid conformation, the current behaviour.
  • On, two runs — pooled sources, size, seed, and the built-library summary.
  • No eligible runs — what the library needs and how to get it, not an empty picker.

States the implementation still needs (not drawn)

  • Building — a first build reads each source trajectory once (about 44 s per 100 ns); the request waits and then shows the key. A later draft can add a progress note if the wait is unacceptable.
  • Refused — the pool is smaller than the size, a source run was deleted, a source has a protein, or the detergent/mapping does not match the library. Each refusal is the server's sentence, shown in the card's status region.
  • Mismatch on rebuild — a rebuilt library whose digest differs from the run's record is a refusal with the restore/copy instruction, never a silent substitution.

Not in this control

  • No per-run editing of individual conformations: the library is an input, not a molecule editor.
  • No mixed-micelle library in this slice: one library per detergent residue.
  • No new dependency: the stratified selection is pure numpy.
