What this view is, and what it is not

It draws files the run wrote. A .gro taken into this viewer is drawn without bonds — the format carries none and this viewer's GRO parser infers none — so the caption names the file rather than implying a connectivity. An all-atom .pdb with no CONECT is drawn with the viewer's own distance guess, which on real chemistry reproduces the molecule. Anything coarse-grained, or any file that carries CONECT, is loaded with the guess switched off.

A structure appearing here is not a statement about the model, and a completed run is not a validated model: the mapping-validation panel is where a model is compared with its reference.

This workspace's scope is the protein-detergent complex runs it queues, and nothing else — an AA-only or osmotic run is not this workspace's to show.

Fourteen runs exist and every one of them is outside this scope: six osmotic series runs and eight single-molecule runs (6 AA-only, 2 AA–CG) — those belong to Detergent validation. Every PDC run was deleted today, so the panel's empty state is the live state. T5's run-type filter on /api/jobs is what makes this list one request instead of a page of 100 filtered in the browser.

Complex runs are drawn in Complexes

This is the overlap the plan names rather than discovering later. Complexes (#pdc) already draws a run's built system and its whole snapshot series, each button carrying the criterion numbers of its own moment — the placement, each phase's end state, and the frames between. A second strip here would be the same strip.

So for a pdc run this panel draws nothing and says where to look, carrying the run across: Open this run in Complexes. That link is the contract Complexes already implements — it reads ?run= at mount and arms the viewer, so a reader arrives on the run already drawn rather than on a placeholder.

The decision for you: keep it delegated (this panel is a door), or make this panel the one place a run is looked at and leave Complexes with only its build door. The second is a bigger change: the snapshot strip's criterion numbers are read from the PDC snapshot index, which is PDC's own.

Why one panel and not two

Same component, two scopes. The registry (dashboard/web/sections.py) declares run-view in both workspaces' tabs; the panel reads the workspace it was mounted under and scopes its run list to that workspace's run types. One viewer means one bond rule — and the second copy is always the one that forgets it.

For your review

Decisions taken, and the ones to judge

Change the specification first, then the code.

Taken, with the reversal cost in the plan

  • One panel (run-view) registered in both workspaces, scoped to each workspace's own run types. Two panels would be two viewers and two bond rules.
  • Structures come from the artifact route — the only door that exists for a run's own stage files.
  • Figures are listed here, zoomed in Runs. No second gallery.
  • No frames, because no route serves one. The strip says so rather than offering buttons that fail.
  • The bond rule: inferBonds: 'none' whenever a file carries CONECT or is coarse-grained; the viewer's own guess only for an all-atom file with no CONECT. The readout reports what the renderer resolved.
  • PDC runs delegate to Complexes, which already draws them.

To judge

  1. The two NGL views that still invent bonds. mapping-ngl.js loads the molecule PDB and the bead PDB with default parameters, and compositions.js loads a preview PDB the server writes with CONECT and doubles it with the distance guess. Fix both in the same change as this panel (one guard, one implementation), or leave them and fix only the new one? My recommendation: fix them.
  2. Frames. Make the frame producer read the AA-only layout so the strip is real for the six AA-only runs, or ship the strip empty with its reason? My recommendation: make it read the layout — the ask names frames.
  3. PDC. Keep it delegated, or make this panel the one place a run is looked at?
  4. A seventh tab in Detergent validation. The rail was built for seven, so nothing moves — but "Run view" now sits beside "Runs". Keep both, or put this inside Runs?
  5. CG bead radii. Size the spheres from the run's own model.json size classes, or draw them uniform and say so?
