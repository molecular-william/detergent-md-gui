Osmotic Series

Set up a concentration series for one carbohydrate: one confined box per molality, run one at a time, and the wall force divided by the box's xy area to give an osmotic pressure.

THE SUGAR

Which carbohydrate this series is for

The solute is one mapped molecule. The box is sized from the mapping's own beads (osmotic.solute_bead_radii reads RADII_NM for each non-virtual bead), so a carbohydrate with no saved CG mapping has no box to build and is not offered a run.

This is what mapping_candidate carries; create_job resolves it to the mapping snapshot the build sizes the box from.

Temperature of the experimental dataset K. It is temperature_k (200–400 K); 308.15 K is maltose's, from Ebrahimi & Sadeghi 2016. A series is compared against the dataset it matches, so this is not a default to leave alone.

Ready. One mapping, its solute files present in /workspace/osmotic/maltose, and the box sized from 8 beads.
THE SERIES

How many conditions, at which concentrations

One run per molality, all sharing a series id. The default is the five measured points at 308.15 K — 0.5, 1.0, 1.5, 2.0, 2.5 molal. The 0.0 control is skipped: it is the same for every sugar, so it is not this series' business to run it — and Add a concentration puts it back for a run that wants it. Molality is confined to the paper's 0.0–2.5 range (osmotic_box.MOLALITY_RANGE); the route's own fallback PAPER_MOLALITIES still names all six, but the panel always sends its set.

    Sent as osmotic_production_ps (500 ns = 500000 ps). 500 ns is the paper's own bar (Methods 5.3) and what every measured condition in the completed series ran. Equilibration is the paper's 10 ns (osmotic_equilibration_ps = 10000) and the trajectory interval is 10 ps (osmotic_output_interval_ps) — both standing, not on this panel.

    The physical setup the run will use

    Read-only, and shown rather than offered: every one of these is fixed by the method or the pipeline, and a control for a value nobody would change from run to run is a control that lies.

    Box5.04156 × 5.04156 × 10.08312 nm (256.286 nm³) — osmotic_box.BOX_NM, the paper's box, fixed for the whole series
    Dividing area25.41733 nm² — osmotic_box.dividing_area_nm2(); the force is divided by this, and the build records it so the analysis never recomputes it
    Confinementflat within 2.52078 nm of the box centre, 1000 kJ/mol/nm² beyond it — the paper's flat-bottom, exactly the quarter box
    WallsPLUMED, one UPPER_WALLS/LOWER_WALLS pair per molecule at KAPPA = 500 — half the paper's 1000 kJ/mol/nm² because PLUMED writes V = KAPPA·(x−AT)²
    Restraintthe reference bead REF: zero size, zero charge, restrained to the box centre in z at 10000 kJ/mol/nm² with refcoord-scaling = all — osmotic.REFERENCE_RESTRAINT
    Saltnone added — the osmometry it compares against measured salt-free solutions
    Seedplacement random.Random(20261006) in the runner; the mdps fix gen-seed = -1. Not a control: a series is comparable because its conditions share these
    mdrun-ntomp 4 -nb gpu -gpu_id 0 -pin on, 1 MPI rank — mdrun_ntomp 4 is the measured best for this ~2500-bead box with the confinement loaded
    SERIES BEHAVIOUR

    How the series runs

    One condition at a time. config/dashboard.json sets max_concurrent_runs: 1 and the coordinator refuses a second run while one is busy. That is a measurement and not a preference: four conditions at once measured ~4.6× slower in aggregate (~291 ns/day each) against ~2400 ns/day for one run alone, and no thread placement recovered it.

    A failed condition is resumed, not restarted. It continues from the run's last usable checkpoint (gmx mdrun -cpi) and is retried up to 3 times before it is called failed. Three is the house ceiling — attempts_max = 3, as in the PDC pipeline. Resuming is new work: the osmotic runner passes no -cpi today, so this is the target the runner task lands, not a control it already honours.

    Then, if a condition still ends failed (after its retries), the series does one of two things — and carrying on is the default. The queue route creates every condition up front and refuses before creating anything if any is wrong, so once the series exists a failed condition does not cancel its siblings, and the reader reports the gap rather than drawing a curve through it.

    Starting a series does not start anything until Start run is pressed, and this panel never queues without that.
