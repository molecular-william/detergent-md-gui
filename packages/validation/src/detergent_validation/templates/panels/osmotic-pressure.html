The validation workspace's seventh panel: it collects the settings `execution/adapters/osmotic.py` reads -- the solute, the concentrations, the duration, the temperature and what the series does when a condition ends failed -- and reads the series as it stands from the route that already reported it. Controls are reached through `form.elements` and class hooks rather than panel-only ids, the same way the protein-detergent fieldset is, because the DOM-id guard renders this page's ids in both directions. Their `name`s carry an `osmotic_` prefix on purpose: `temperature_k` and `mapping_candidate` are already used by the single-molecule form in this same document, and a second `[name=temperature_k]` turns every `page.locator('[name=temperature_k]')` in the browser tier into a strict-mode violation. Osmotic Series

Set up a concentration series for one carbohydrate: one confined box per molality, run one at a time, and the wall force divided by the box's xy area to give an osmotic pressure.

THE SUGAR

Which carbohydrate this series is for

The solute is one mapped molecule. The box is sized from the mapping's own beads (osmotic.solute_bead_radii reads RADII_NM for every non-virtual bead), so a carbohydrate with no saved CG mapping has no box to build and is not offered a run.

This is what mapping_candidate carries; create_job resolves it to the mapping snapshot the build sizes the box from.

Temperature of the experimental dataset K. It is temperature_k (200–400 K); 308.15 K is maltose's, from Ebrahimi & Sadeghi 2016. A series is compared against the dataset it matches, so this is not a default to leave alone.

THE SERIES

How many conditions, at which concentrations

One run owns the whole series. The concentrations below are its conditions: it runs them one at a time, each in its own directory with its own checkpoint, so a condition that dies resumes where it stopped and the ones that finished are not repeated. The default is the five measured points at 308.15 K — 0.5, 1.0, 1.5, 2.0, 2.5 molal. The 0.0 control is skipped: it is the same for every sugar, so it is not this series' business to run it — and Add a concentration puts it back for a run that wants it. Molality is confined to the paper's 0.0–2.5 range (osmotic_box.MOLALITY_RANGE); the route's own fallback PAPER_MOLALITIES still names all six, but this panel always sends its set.

    Sent as osmotic_production_ps (500 ns = 500000 ps). 500 ns is the paper's own bar (Methods 5.3) and what every measured condition in the completed series ran. Equilibration is the paper's 10 ns (osmotic_equilibration_ps = 10000) and the trajectory interval is 10 ps (osmotic_output_interval_ps) — both standing, not on this panel.

    SERIES BEHAVIOUR

    How the series runs

    One condition at a time. config/dashboard.json sets max_concurrent_runs: 1 and the coordinator refuses a second run while one is busy. That is a measurement and not a preference: four conditions at once measured ~4.6× slower in aggregate (~291 ns/day each) against ~2400 ns/day for one run alone, and no thread placement recovered it.

    Then, if a condition still ends failed, the series does one of two things — and carrying on is the default. The queue route creates every condition up front and refuses before creating anything if any is wrong, so once the series exists a failed condition does not cancel its siblings unless the series asked it to, and the reader reports the gap rather than drawing a curve through it.

    Starting a series does not start anything until Start series is pressed, and this panel never queues without that.
